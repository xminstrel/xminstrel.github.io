这一部分是第四章 4.5 查表程序设计，也是 8051 汇编语言中非常实用的一种程序设计方法。

你之前已经学过 `DB` 伪指令、`MOVC` 指令、`DPTR` 和 `PC`，这道题正好把它们全部联系起来。

查表程序的核心思想是：提前把需要的数据放在 ROM 中，运行时根据输入值找到对应的数据，而不是每次都重新计算。

我们先理解查表的原理，再逐条分析老师的程序，重点解释你可能比较疑惑的两个地方：

- 为什么要执行 `ADD A,#03H`？
    
- `MOVC A,@A+PC` 为什么可以读取 ROM 中的数据？
    

## 一、首先理解什么是查表程序

假设我们需要把十六进制数字转换为 ASCII 码。

例如：

|十六进制数字|对应字符|ASCII 码|
|---|---|---|
|0H|'0'|30H|
|1H|'1'|31H|
|2H|'2'|32H|
|3H|'3'|33H|
|…|…|…|
|9H|'9'|39H|
|AH|'A'|41H|
|BH|'B'|42H|
|CH|'C'|43H|
|DH|'D'|44H|
|EH|'E'|45H|
|FH|'F'|46H|

例如输入的是十六进制数 `0BH`，我们希望得到字符 `'B'` 的 ASCII 码 `42H`。

一种方法是编写多个条件判断，分别处理 0～F。

但是这样程序会比较长。

另一种更简单的方法是：提前把 0～F 对应的 16 个 ASCII 码存放在 ROM 中，形成一张表。

```
ASCTAB:
    DB '0','1','2','3','4','5','6','7'
    DB '8','9','A','B','C','D','E','F'
```

这里的 `DB` 是 Define Byte（定义字节）。

它会让汇编器依次生成 16 个字节的数据。

例如：

- `'0'` 实际保存的是 ASCII 码 `30H`。
    
- `'5'` 实际保存的是 ASCII 码 `35H`。
    
- `'B'` 实际保存的是 ASCII 码 `42H`。
    

注意：`'B'` 与 `0BH` 不相同。前者是字符 B 的 ASCII 码 42H，后者是一个数值 11。

每格上方是偏移量，中间是字符，下方是实际存储的 ASCII 码。

我们定义：

\[ \text{查表地址}=\text{表格首地址}+\text{偏移量} \]

例如，输入 `0BH`：

\[ 0BH=11 \]

就从表格首地址开始，向后偏移 11 个字节，找到字符 `'B'`，读取其 ASCII 码：

\[ \boxed{42H} \]

所以查表程序只需要解决两个问题：

1. 表格从哪个地址开始？
    
2. 要读取表格中的第几个字节？
    

8051 使用 `MOVC` 指令来完成这个操作。

## 三、逐条讲解老师的程序

老师的程序是：

```
    MOV A,R0
    ANL A,#0FH
    ADD A,#03H
    MOVC A,@A+PC
    MOV R0,A
    SJMP $

ASCTAB:
    DB '0','1','2','3','4','5','6','7'
    DB '8','9','A','B','C','D','E','F'
```

假设一开始：

\[ R0=5BH \]

题目只要求转换 R0 的低 4 位，因此我们要把 `BH` 转换成字符 `'B'` 的 ASCII 码 `42H`。

### 第一步：MOV A,R0

```
MOV A,R0
```

把 R0 的值送入 A：

\[ A=5BH \]

### 第二步：ANL A, #0FH

```
ANL A,#0FH
```

`ANL` 是按位与运算。

把两个数写成二进制：

```
    0101 1011    5BH
AND 0000 1111    0FH
    ---------
    0000 1011    0BH
```

得到：

\[ \boxed{A=0BH} \]

为什么要这样操作？

因为题目只关心 R0 的低 4 位，而高 4 位可能是任何值。

`ANL A,#0FH` 的作用就是：

保留低 4 位，将高 4 位全部清零。

这是一种非常常用的位屏蔽操作。

### 第三步：ADD A, #03H

```
ADD A,#03H
```

现在：

\[ A=0BH \]

执行后：

\[ A=0BH+03H=0EH \]

这里你可能会疑惑：

我们原本要找表格中偏移量为 0BH 的字符，为什么还要加 3？

这恰恰是这道题最关键的部分。

## 四、为什么要加 03H？重点理解 PC 的作用

我们先来看：

```
MOVC A,@A+PC
```

这条指令的功能是：

\[ \boxed{A\leftarrow ROM[PC+A]} \]

这里的 PC 指的是执行 MOVC 时，已经指向下一条指令的程序计数器值。

也就是说，`MOVC A,@A+PC` 并不是自动从 `ASCTAB` 标号开始查表的！

它是以 MOVC 后面紧接着的指令地址为基准进行查找。

### 1. 看看程序的实际存储位置

为了方便理解，假设这段程序从 `ORG 0000H` 开始存放。

|程序存储器地址|指令或数据|占用字节|
|---|---|---|
|0000H| `MOV A,R0` |1|
|0001H～0002H| `ANL A,#0FH` |2|
|0003H～0004H| `ADD A,#03H` |2|
|0005H| `MOVC A,@A+PC` |1|
|0006H| `MOV R0,A` |1|
|0007H～0008H| `SJMP $` |2|
|0009H| `ASCTAB: DB '0',...` |每个元素 1|

当 CPU 执行到：

```
MOVC A,@A+PC
```

时，该指令的地址是 0005H。

因为 MOVC 占用 1 字节，取指后 PC 已经指向：

\[ PC=0006H \]

但是表格实际开始于：

\[ ASCTAB=0009H \]

所以：

\[ 0009H-0006H=3 \]

因此必须额外增加偏移量 3。

\[ \boxed{\text{真实查表偏移量}=\text{数字索引}+3} \]

这就是：

```
ADD A,#03H
```

的真正作用。

PC 相对查表的地址关系

0005H

MOVC A,@A+PC

当前 MOVC 指令

0006H

MOV R0,A

MOVC 使用的 PC 基准地址

0007H

SJMP $（第 1 字节）

0008H

SJMP $（第 2 字节）

0009H

ASCTAB: DB '0'

查找表首地址

从 0006H 向后偏移 3 字节到达表首地址 0009H

### 2. 继续计算刚才的例子

我们前面已经得到：

\[ A=0EH \]

现在执行：

```
MOVC A,@A+PC
```

有效地址为：

\[ PC+A=0006H+0EH \]

\[ =\boxed{0014H} \]

0014H 对应表格中偏移量为 0BH（十进制 11）的元素：

```
DB '8','9','A','B','C','D','E','F'
```

所以读取的是字符 `'B'` 的 ASCII 码：

\[ \boxed{A=42H} \]

这就完成了查表。

## 五、最后两条指令是什么作用？

### 1. MOV R0,A

```
MOV R0,A
```

查表结果已经放在 A 中：

\[ A=42H \]

但题目要求将结果送回 R0，因此：

\[ R0\leftarrow A \]

最终：

\[ \boxed{R0=42H} \]

### 2. SJMP $

```
SJMP $
```

表示程序在当前位置无限循环。

为什么需要这条指令？

因为后面紧接着存放的是 DB 定义的数据表，而不是正常需要执行的程序指令。

如果不加 `SJMP $` 等跳转，CPU 可能继续顺序取指，把数据表中的字节当作机器指令执行。

所以这条指令也起到了隔离程序和数据表的作用。

## 七、MOVC A,@A+PC 和 MOVC A,@A+DPTR 有什么区别？

这是第四章查表程序设计最重要的两个指令。

|对比| `MOVC A,@A+PC` | `MOVC A,@A+DPTR` |
|---|---|---|
|访问的存储器|程序存储器 ROM|程序存储器 ROM|
|基准地址|PC|DPTR|
|偏移量|A|A|
|是否需要设置 DPTR|否|是|
|特点|适合附近的数据表|适合任意指定位置的数据表|
|注意事项|必须计算与表格之间的距离|需要先装入表格地址|

其实，我更推荐你考试时优先掌握 `MOVC A,@A+DPTR`，因为它不需要像老师这道题一样计算 `+03H`。

例如，同一道题可以改写成：

```
ORG 0000H

    MOV DPTR,#ASCTAB
    MOV A,R0
    ANL A,#0FH
    MOVC A,@A+DPTR
    MOV R0,A
    SJMP $

ASCTAB:
    DB '0','1','2','3','4','5','6','7'
    DB '8','9','A','B','C','D','E','F'

END
```

我们重点看：

```
MOV DPTR,#ASCTAB
MOV A,R0
ANL A,#0FH
MOVC A,@A+DPTR
```

因为 DPTR 已经直接指向 ASCTAB，所以：

\[ \boxed{\text{查表地址}=ASCTAB+A} \]

不需要再添加偏移补偿量 3。

例如 A=0BH：

\[ \text{查表地址}=ASCTAB+0BH \]

直接找到字符 `'B'`。

相比 PC 相对查表，这种方法更直观，也不容易因为增加或删除指令而导致偏移量错误。

## 八、总结：考试中怎么自己写查表程序？

以后遇到“根据一个输入值查找对应数据”的题目，我建议按照以下步骤思考：

1. 确定输入范围：例如 0～9、0～F。
    
2. 定义数据表：使用 `DB` 依次存放每个输入对应的数据。
    
3. 设置表格首地址：使用 DPTR，或者采用 PC 相对查表。
    
4. 确定偏移量：使 A 中保存正确的表格索引。
    
5. 执行 MOVC 查表：将 ROM 对应地址的数据读入 A。
    
6. 保存结果：将 A 中的查表结果存入要求的寄存器或 RAM 单元。
    

最后给你一个非常重要的记忆表：

|指令|记忆方法|
|---|---|
| `DB` |建立数据表|
| `MOV DPTR,#TAB` |找到表头|
| `MOV A,#n` |选择第 n 个元素（从 0 开始）|
| `MOVC A,@A+DPTR` |根据表头和偏移量查表|
| `MOVC A,@A+PC` |根据当前 PC 和偏移量查表|

你现在最需要掌握的是两点：第一，`MOVC` 的有效地址如何计算；第二，为什么 PC 相对查表时可能需要额外补偿偏移量。

这两点搞明白之后，数码管显示码查表、ASCII 码转换、平方表、温度数据查表等程序，实际上都可以使用同样的结构来编写。
