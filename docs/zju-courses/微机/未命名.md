## 一、什么是住宅 IP

你可以把 **IP 地址** 想象成你上网时的"门牌号"。你访问任何网站，对方都能看到这个门牌号，从而大致知道你在哪个国家、哪个城市，以及你用的是哪家网络公司。

IP 大致分两类：

- **机房 IP（数据中心 IP）**：来自云服务器公司（如亚马逊、谷歌云、各种 VPS 厂商）。好比"写字楼里的共享办公室"，成千上万人共用，网站一看就知道"这不是普通家庭"。
- **住宅 IP**：由当地普通宽带运营商（比如美国的 Comcast、AT&T）分配给家庭用户的 IP。好比"居民小区里的一户人家"，网站会认为你就是一个当地的普通用户。

## 二、为什么大家需要住宅 IP？

很多网站有**风控系统**，对机房 IP 特别敏感。用机房 IP 访问时，常见的问题有：

- 频繁弹出验证码（"请证明你不是机器人"）
- 注册账号失败，或注册后很快被封
- 某些流媒体、AI 服务、电商平台直接拒绝访问
- 被提示"检测到你在使用代理"

换成住宅 IP 后，网站会把你当成当地真实居民，这些问题会少很多。所以住宅 IP 常被用来**稳定使用对 IP 要求严格的服务**，比如注册和维护海外账号、跨境电商、看海外流媒体等。当然对我们来说，最主要的作用就是访问国外的 AI 服务了，例如 Claude 几乎是必须使用住宅 IP 才能稳定使用，而其他 AI 使用住宅 IP 则更难出现降智情况。

住宅 IP 一般有两种：

- **静态住宅 IP**：一个固定 IP 长期给你用，适合养账号、长期登录同一个服务。
- **动态住宅 IP**：IP 不断轮换，适合爬虫、数据采集，不适合养号。

普通用户一般买的是**静态住宅 IP**，通常按月、按个计费。

## 三、住宅 IP 可以直接使用吗？

**要看你在哪里上网。**

- **如果你人在海外**：可以直接用。在软件或浏览器里填入服务商给你的地址、端口、账号密码就行。
    
- 如果你人在中国大陆
    
    ：通常
    
    不能直接用，或者很不稳定
    
    。原因有两个：
    

1. 住宅 IP 服务商提供的多是 **SOCKS5 或 HTTP** 这类"普通代理协议"，它们**没有加密伪装**，流量特征很明显，跨境时很容易被识别和阻断。
2. 住宅 IP 本身的线路是在海外，从国内直连过去，延迟高、丢包多，体验很差。

## 四、为什么要搭配"机场"使用？

"机场"指的是提供翻墙节点订阅的服务。两者各有所长：

- **机场**：擅长"出国"，协议有加密和伪装，线路经过优化，速度快、稳定，但出口通常是机房 IP。
- **住宅 IP**：擅长"伪装身份"，出口是干净的住宅 IP，但自己不擅长跨境。

把它们**串起来**（这叫"链式代理"或"前置代理"），流量路径就变成：

> 你的电脑 → **机场节点**（负责安全快速地出境）→ **住宅 IP**（负责最后一跳的身份）→ 目标网站

这样目标网站看到的是住宅 IP，而跨境那一段由机场负责。实际操作中一般用 Clash Verge、mihomo 等客户端，在配置里给住宅 IP 节点指定一个"前置代理"即可。

## 五、如何使用自己的住宅 IP

### 1. 先确认你需不需要自己串联

住宅 IP 厂商通常提供一组 **SOCKS5 或 HTTP 代理信息**（地址、端口、用户名、密码）。这类协议没有加密和流量伪装，不适合从国内直连，如下图中的**原始代理**。有的厂商除了提供原始代理外，还提供了**中转代理**。如果厂商提供了中转代理，意味着厂商已经帮你完成了串联，直接把厂商给的节点导入 Clash Verge Rev 即可，不需要看后面的内容，但是厂商的中转代理往往会设备数量进行限制，如我这个厂商限制了使用中转代理的设备数量最多为 2 个。

![](https://file.cc98.org/v4-upload/d/2026/1019/ey4cdmak.webp)

假如厂商不提供中转或者中转代理的设备数量不够用的时候，需要我们自己完成串联，有两种做法：

- **方式一：在服务器上配置住宅 IP**（串联发生在服务器端）
- **方式二：在本地客户端配置链式代理**（串联发生在你的电脑上）

两种方式的区别如下：

||方式一：服务器端串联|方式二：本地链式代理|
|---|---|---|
|链路|电脑 → 自建服务器（服务器出站走住宅 IP）→ 网站|电脑/服务器（客户端负责串联）→ 前置代理 → 住宅 IP → 网站|
|是否需要自己的服务器|需要|不一定，可用代理订阅服务的节点作前置|
|客户端配置难度|简单，当普通节点用|稍复杂，要设置前置代理|
|多设备（手机、平板）|方便，所有设备导入同一个节点即可|每台设备都要单独配置串联|
|住宅 IP 白名单|容易，只需绑定服务器 IP|前置节点 IP 可能会变，白名单不好设|
|维护成本|要自己维护服务器|基本只维护客户端|

由于方案一涉及到购买海外的服务器，会产生额外的开销，在这里我就不展开了。接下来我只讲本地链式代理的流程

### 2. 在本地客户端配置链式代理

### 原理

由你电脑上的 Clash Verge 负责串联：先连前置代理出境，再通过前置代理连接住宅 IP。前置代理来自你日常使用的机场。

### 客户端步骤（Clash Verge 图形界面）

不同版本的菜单名称可能略有差异，以我的界面为例。

**第 1 步：准备配置文件**

1. 进入 **配置（订阅）** 页面。
2. 有代理订阅：直接导入订阅链接。

![](https://file.cc98.org/v4-upload/d/2026/1019/gv03emal.webp)

**第 2 步：添加住宅 IP 节点并指定前置代理**

1. 右键配置 → **编辑节点**，新增节点。
2. 类型选 **SOCKS5** 或 **HTTP**，填写住宅 IP 的地址、端口、用户名、密码（划重点：此处的格式一定要正确，供应商一般提供的格式名为“协议://IP:端口:用户名:密码”，但是 Clash Verge 智能识别 `@` 的代理链接格式）。
3. 保存。

> 如果你的版本节点表单里没有前置代理选项：可以在 **编辑代理组** 中新建一个类型为 **relay（链式中转）** 的代理组，按"前置节点 → 住宅 IP"的顺序放入。注意 Mihomo 内核更推荐前置代理方式，relay 类型在新版本中可能不再维护。

![](https://file.cc98.org/v4-upload/d/2026/1019/nvpczbkk.webp)

**第 3 步：配置链式代理**

1. 打开代理页面：点击左侧「代理」。
2. 开启链式代理：点击右上角「链式代理」。
3. 选择入口节点：点击一个机场节点。
4. 选择出口节点：如点击住宅 SOCKS5 代理节点。
5. 确认代理顺序：右侧应显示「机场节点 → 住宅代理」。
6. 连接代理链：点击右侧绿色「连接」按钮。

> 如果在链式代理中出口节点显示超时是正常现象，因为住宅代理可能无法从你的本地网络直接连接，但可以通过前置机场节点访问。只要完整代理链能正常工作，单独测试超时不一定有问题。

![](https://file.cc98.org/v4-upload/d/2026/1019/kin4top4.webp)

**第 4 步：启用**

1. 主界面选 **规则模式**，打开 **系统代理**（或 **TUN 模式**）。
2. 在 **代理** 页面确认"住宅出口"组选中的是"住宅 IP"。

**第 5 步：验证**

1. 对"住宅 IP"节点做延迟测试，能测出数值说明链路已通。
2. 打开 IP 查询网站，确认：

- 显示的是**住宅 IP**，而不是前置代理的 IP；
- IP 类型为住宅（Residential / ISP），风险分数较低。

![](https://file.cc98.org/v4-upload/d/2026/1019/4gymriyp.webp)

### 服务器步骤：让服务器上的程序使用住宅 IP

如果你需要在 Linux 服务器上运行脚本或其他程序，可以由服务器上的 Mihomo 完成串联，再给程序提供一个本机代理地址。

> 服务器上的程序 → 本机 Mihomo → 机场节点 → 住宅代理 → 目标网站

下面只配置服务器本机程序使用的代理，无需开放公网端口。

#### 第 1 步：下载项目并准备内核

项目地址：[mihomo-residential-proxy](https://github.com/PangSMPang/mihomo-residential-proxy)。仓库已经包含 Linux amd64 / arm64 内核、配置模板和中文说明，无需另找内核文件。

在服务器终端执行以下命令（需要已安装 Git、Bash、gzip 和 sha256sum）：

```
git clone https://github.com/PangSMPang/mihomo-residential-proxy.git
cd mihomo-residential-proxy
bash prepare.sh
```

也可以在仓库页面点击 **Code → Download ZIP**，将完整项目上传到服务器并解压，进入项目目录后执行 `bash prepare.sh`。

准备脚本会识别服务器架构、校验并解压内核，再从 `config.example.yaml` 生成供自己填写的 `config.yaml`。已有配置会被保留。

> 这个代码是让 Codex 根据我自己的订阅信息生成的，如果发现不适用可以让 AI 根据自己的订阅信息修改一下。

#### 第 2 步：填写自己的代理信息

打开生成的 `config.yaml`，只需修改标有【必填】的 5 项：

|字段|填写内容|
|---|---|
|机场订阅 `url` |自己的 Mihomo/Clash 格式节点订阅链接|
|住宅节点 `server` |住宅代理的 IP 或域名|
|住宅节点 `port` |住宅代理端口，填写数字|
|住宅节点 `username` |住宅代理用户名|
|住宅节点 `password` |住宅代理密码|

`server` 只填 IP 或域名，不要把整条代理链接粘进去。保留字符串两侧的引号；端口填写数字。默认使用 SOCKS5，如果商家提供 HTTP 代理，将 `type: socks5` 改为 `type: http` 即可。

`dialer-proxy: AIRPORT` 是指定机场前置的关键设置，应保留。机场节点通过订阅自动读取，默认按顺序使用可用节点。如果需要指定某个前置节点，可以把节点名称和需求告诉 AI，让它协助修改配置。

#### 第 3 步：检查并启动

填写完成后，在项目目录中执行：

```
bash start.sh
```

启动脚本会先检查是否还留有占位符，再校验配置并以前台方式启动。首次运行需要下载机场订阅，服务器须能访问订阅地址和前置节点。出现错误时，先查看当前终端的日志。

保持它运行，打开另一个 SSH 窗口完成下一步验证。验证成功后，可以回到第一个窗口按 `Ctrl+C` 停止进程，再改为后台运行：

```
nohup bash start.sh >mihomo.log 2>&1 &
```

查看日志：

```
tail -n 50 mihomo.log
```

后台运行不包含开机自启，也不要在已有实例运行时重复启动。

#### 第 4 步：验证出口并给程序使用

执行以下命令，检查最终出口：

```
curl --noproxy "" --connect-timeout 10 --max-time 30 \
  --proxy http://127.0.0.1:18080 https://api.ipify.org
```

返回值应与商家提供的住宅**出口 IP**一致。有些商家的接入地址与出口 IP 不同，以商家后台为准。能获取到正确出口，说明本次请求通过了代理链；是否被目标网站判定为住宅 IP、能否正常登录，还需分别验证。

在需要使用代理的程序中填写：

```
HTTP 代理：http://127.0.0.1:18080
SOCKS5 代理：socks5h://127.0.0.1:18080
```

`socks5h` 适用于 curl 等支持这种写法的工具，表示由代理解析目标域名；其他程序按其 SOCKS5 设置填写。

支持代理环境变量的程序，也可在启动程序的同一个终端设置：

```
export http_proxy=http://127.0.0.1:18080
export https_proxy=http://127.0.0.1:18080
```

随后运行程序。只有明确使用这个代理地址的程序请求会走住宅出口；Docker 容器等独立网络环境需要另行配置。更多排查方法见[详细使用说明](https://github.com/PangSMPang/mihomo-residential-proxy/blob/main/%E4%BD%BF%E7%94%A8%E8%AF%B4%E6%98%8E.md)。
