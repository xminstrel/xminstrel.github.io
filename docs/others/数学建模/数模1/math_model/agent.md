# Math Modeling Agent Instructions

本项目是浙江大学第二十四届大学生数学建模竞赛 B 题“浙超”分组方案。
所有后续 agent 必须优先遵守本文件；若题面 PDF、比赛通知或用户直接指令与本文件冲突，以用户/题面为准，并在日志中说明取舍。

## 工作目标

1. 不只给出可行分组，而是迭代寻找在数学思想、可解释性、可复现性和竞赛论文表达上都尽可能强的方案。
2. 使用题面信息作为硬约束，同时广泛引入公开数据与高质量文献作为软约束和论证依据。
3. 每一次建模、数据、算法和实验调整都必须留下可追溯痕迹，便于论文附录与 AI 使用详情说明。
4. 使用专用 conda 环境 `zju_math_model`：环境路径为 `D:\Anaconda\envs\zju_math_model`。所有后续脚本和实验优先用 `D:\Anaconda\envs\zju_math_model\python.exe ...` 执行；若必须经 conda 调用，则用 `conda run -n zju_math_model python ...`。新增依赖必须记录到 `requirements-zju_math_model.txt` 或迭代日志。

## 项目目录约定

- `docs/research/`: 文献、网页资料、数据源说明和引用记录。
- `docs/prompts/`: 关键提示词、AI 交互摘要和可复用主 Prompt。
- `docs/modeling/`: 数学模型、算法设计、评价指标和论文写作素材。
- `data/raw/`: 原始公开数据，必须保留来源说明。
- `data/processed/`: 清洗后的可复现实验数据。
- `src/`: 可运行源代码。
- `experiments/`: 每轮实验配置、结果、图表和诊断。
- `iterations/`: 迭代日志。每轮必须写明动机、改动、结果、失败点、下一步。
- `output/`: 最终分组、场地方案、图表和论文可用材料。

若目录不存在，先创建目录。

## 题面硬约束

- 参赛单位共 64 个：浙江省 11 个市级队，20 个县级市和 33 个县合称县级队。
- 第一阶段分 16 个小组，每组 4 支队伍，单循环比赛。
- 小组前两名进入 32 强淘汰赛。
- 市级队必须分配在不同小组。
- 市级队不得与该市代管县级队同组。
- 同一市代管县级队应尽量不同组。
- 分组方案需要给出多个，并从不同维度比较优劣。
- 需要设计可行抽签方案，使随机抽签结果满足约束并具有较好性质。
- 需要选择 8 个市/县作为小组赛地点，每个地点承办 2 个小组。
- 需要基于数学模型和定量分析给出赛制建议。

## 建模原则

1. 先把硬约束形式化，再设计软目标函数；不要把偏好伪装成硬约束。
2. 优先考虑图论、组合优化、整数规划、约束规划、随机抽样、鲁棒优化、多目标优化、设施选址和公平性度量。
3. 分组方案至少比较这些维度：
   - 约束满足度；
   - 地域分散与同属地回避；
   - 旅行距离/时间或交通便利性；
   - 城市影响力与覆盖面；
   - 竞技公平性和观赏性；
   - 抽签透明度、可执行性与随机性；
   - 对赛制建议的支撑能力。
4. 若缺少真实球队实力数据，应明确建模假设，并可用人口、GDP、足球基础、历史赛事、城市等级等公开数据构造代理指标；代理指标必须做敏感性分析。
5. 不为了炫技而堆方法。每个高级方法都必须对应题目中的实际目标或约束。

## 迭代规则

每一次迭代在 `iterations/` 新建或追加日志，文件名建议为：

`YYYY-MM-DD_iterNN_<short-name>.md`

日志必须包含：

- 迭代目标；
- 新增数据或文献；
- 数学模型/算法变化；
- 关键参数；
- 运行命令；
- 结果摘要；
- 与上一轮的量化比较；
- 失败、风险和下一步。

实验结果应保存到 `experiments/iterNN/`，不要只写在聊天记录里。

## 数据与引用

- 所有外部数据必须记录来源、访问日期、字段含义、许可或使用限制。
- 公开网页、统计年鉴、政府数据、地图/经纬度服务、论文和教材都应进入引用清单。
- 论文中引用网上资源时按题面要求记录“资源标题、网址、访问时间”。
- AI 生成内容必须在 `docs/prompts/ai_usage_log.md` 中记录工具、日期、目的、关键提示词、采纳与人工修改情况。

## 代码与验证

- 所有算法必须可复现运行，优先写成命令行脚本。
- 随机算法必须固定并记录随机种子，同时允许多 seed 重复实验。
- 对硬约束写自动检查函数；每次输出方案前先运行检查。
- 对多目标评价写统一评分函数，并输出分项指标而非只输出总分。
- 最终至少保留：
  - 若干组可行分组方案；
  - 抽签流程模拟与合规性验证；
  - 场地选择方案；
  - 赛制建议的定量依据；
  - 可复现实验脚本和依赖说明。
