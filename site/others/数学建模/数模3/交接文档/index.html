    数模3最终成果交接文档

    本文档用于把 数模3 文件夹交接给组员。当前文件夹已经作为最终建模成果整理，主线口径为：问题一推荐分组 D003；问题三和问题四均基于 D003 重新计算；旧的 D001 相关输出只作为中间结果保留。

    一、优先阅读顺序

    组员第一次接手时，建议按以下顺序阅读：

    1. 建模总方案.md
    2. 最终论文主体内容，包含数据、图染色、问题一至问题四的完整模型、公式和结果。
    3. 输出文件口径说明.md
    4. 说明哪些输出文件是最终口径，哪些只是中间结果。
    5. 运行说明.md
    6. 给出从数据融合到赛制仿真的复现命令。
    7. 最终方案检查评估.md
    8. 记录已经检查和修正过的问题，适合答辩或论文自查时引用。
    9. 各问题对应输出文件：
    10. 问题一：outputs_selection/问题一方案选择说明.md
    11. 问题二：outputs_lottery/final_draw_scheme.md
    12. 问题三：outputs_venues_selected/venue_solution.md
    13. 问题四：outputs_tournament_selected/simulation_summary.md

    二、最终结论口径

    最终成果统一采用以下结论：

    问题 最终口径

    问题一分组 推荐 D003，而不是 direct_score 最高的 D001

    三、目录与文件说明

    1. 主文档

    文件 作用
    建模总方案.md 最终总方案，写论文时优先参考
    最终方案.md 阶段性最终方案文本，可作为辅助材料
    最终方案摘要.md 简短摘要，适合写论文摘要或汇报开头
    最终方案检查评估.md 公式、逻辑、结果口径检查记录
    问题三选址模型与准确性检查.md 问题三选址部分的专项检查
    输出文件口径说明.md 最终输出与旧输出的区别
    运行说明.md 复现命令
    交接文档.md 当前交接说明

    2. 数据目录

    路径 作用
    data/final_teams.csv 最终融合后的 64 支队伍指标表，所有模型统一使用该文件
    data/data_sources.csv 数据来源标记
    data/data_summary.json 数据覆盖统计
    data/数据来源与融合说明.md 数据融合说明

    数据来源需要注意：队伍名单来自赛题结构化数据；GDP、人口优先使用浙江统计年鉴解析数据；经纬度、文旅、体育基础等仍为代理数据。论文中应写“潜在体育实力代理指标”和“赛事关注度代理指标”，不要写成真实球队实力。

    3. 代码文件

    文件 作用
    build_enriched_data_and_graph.py 生成融合数据，并做图染色分析
    select_final_group_scheme.py 从 D001-D005 中按 TOPSIS 选择最终问题一方案
    compare_generation_methods.py 比较候选池抽样法和直接寻优法，统一 TOPSIS 后 D003 仍最优

    另外，部分核心算法代码放在上级目录的 分组评价模型 中，数模3 调用这些代码生成最终结果：

    外部代码 作用
    分组评价模型/group_evaluator.py 候选池生成、指标计算、TOPSIS 排序
    分组评价模型/direct_optimizer.py 问题一可行域直接寻优
    分组评价模型/lottery_draw.py 问题二方案池抽签
    分组评价模型/venue_selector.py 问题三赛地选择
    分组评价模型/tournament_simulator.py 问题四赛制仿真

    outputs_tournament/ 早期基于 D001 赛地结果的仿真，已被 outputs_tournament_selected/ 替代

    四、复现流程

    所有命令均在仓库根目录运行：

    cd D:\xminblog\docs\others\数学建模

    1. 生成融合数据和图染色分析

    python .\数模3\build_enriched_data_and_graph.py

    主要输出：

    • 数模3/data/final_teams.csv
    • 数模3/outputs_graph/graph_coloring_analysis.md

    2. 问题一直接寻优

    python .\分组评价模型\direct_optimizer.py --teams .\数模3\data\final_teams.csv --starts 80 --steps 6000 --keep 5 --seed 2026 --initial-pool 160 --output-dir .\数模3\outputs_direct

    主要输出：

    • 数模3/outputs_direct/direct_top_schemes.md
    • 数模3/outputs_direct/direct_top_schemes.json

    3. 问题一最终方案选择

    python .\数模3\select_final_group_scheme.py

    主要输出：

    • 数模3/outputs_selection/问题一方案选择说明.md
    • 数模3/outputs_selection/selected_scheme.csv

    4. 候选池方法补充比较

    python .\分组评价模型\group_evaluator.py --teams .\数模3\data\final_teams.csv --candidates 1500 --seed 2026 --alpha 0.5 --output-dir .\数模3\outputs_candidate_eval
python .\数模3\compare_generation_methods.py

    主要输出：

    • 数模3/outputs_candidate_eval/top_schemes_comparison.md
    • 数模3/outputs_method_compare/问题一分组生成方法对比.md

    5. 问题二公开抽签

    python .\分组评价模型\lottery_draw.py --teams .\数模3\data\final_teams.csv --candidates 3000 --top-k 100 --seed 2026 --alpha 0.5 --draw-seed 7392048615 --output-dir .\数模3\outputs_lottery

    主要输出：

    • 数模3/outputs_lottery/scheme_pool.sha256
    • 数模3/outputs_lottery/final_draw_scheme.md
    • 数模3/outputs_lottery/draw_record.json

    当前抽签示例结果：

    6. 问题三赛地选择

    可以按下面方式分工：

    组员任务 建议负责内容 主要参考文件

    问题二 公开抽签流程、现场数字串、哈希抽取公式 建模总方案.md 第五节，outputs_lottery/lottery_process.md

    六、关键注意事项

    1. 不要把 D001 写成最终推荐分组。D001 是 direct_score 最高，但最终 TOPSIS 综合评价选择 D003。
    2. 不要引用 outputs_venues/ 和 outputs_tournament/ 作为最终结果，它们是早期口径。
    3. D003 是当前数据和计算预算下的高质量近优解，不要声称是全可行域严格全局最优。
    4. 抽签结果 P0039 是问题二“公开抽签机制”的示例；如果论文问题一要求模型推荐方案，仍写 D003。
    5. P0039 的 TOPSIS 分数和 D003 的 TOPSIS 分数归一化集合不同，不能直接比较大小。
    6. 体育实力、关注度、文旅、体育基础等指标含代理变量，论文中要明确“代理指标”或“相对评价指标”。
    7. 赛地距离基于行政点近似坐标，不是真实球场交通时间；实际落地需要换成真实场馆、交通和住宿数据。

    七、最终答辩口径

    可以用下面几句话概括整个方案：

    本文先基于赛题队伍名单和统计年鉴数据构造 64 支队伍的统一指标表，再用图染色说明行政冲突约束下至少需要 11 类颜色，但最终采用 16 组是为了满足每组 4 队、8 个赛地每地 2 组和淘汰赛衔接。问题一通过硬约束筛选、候选池抽样、可行域直接寻优和 AHP-熵权-TOPSIS 综合评价，最终推荐 D003。问题二设计优质方案池公开随机抽签，用方案池哈希和现场数字串共同确定抽签结果。问题三在 D003 基础上选择 8 个赛地，兼顾出行、公平、区域覆盖和赛事普及。问题四通过蒙特卡洛仿真比较赛制，推荐 16 组单循环加 32 强单败淘汰的赛制。

    最终方案可解释、可复现、可检查，但不声称全局最优；它是在当前数据、代理指标体系和计算预算下得到的高质量近优建模结果。
